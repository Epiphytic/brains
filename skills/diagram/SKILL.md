## Invocation

```
/brains:diagram "<description>" [--type <type>]
```

`--type` values: `flowchart`, `state`, `c4`. If omitted, infer from description:
states/lifecycle/transitions → `state` | system context/containers/actors → `c4` | default → `flowchart`

## Routing Table

Load type reference lazily (only when generating that type):

| `--type` | Load |
|---|---|
| `flowchart` | `skills/diagram/references/flowchart.md` |
| `state` | `skills/diagram/references/state.md` |
| `c4` | `skills/diagram/references/c4.md` |

Always load on any diagram generation: `skills/diagram/references/renderer-conventions.md` and `skills/diagram/references/storage-conventions.md`

## Generation Steps

1. Load per-type reference + storage/renderer conventions.
2. Generate Mermaid source (begin with auto-trigger marker — see Self-Correction section).
3. Sanitize ADR stem: strip any path separators (`/`, `\`, `..`) from the stem. The output path MUST resolve under `docs/adr/diagrams/` only.
4. Detect renderer per renderer-conventions.md; produce SVG if possible.
5. Write `.mmd` first (from generated source). Render to SVG from the `.mmd` file using the detected renderer. If renderer succeeded, write `.svg`.
6. Write or update ADR `## Diagram` section per storage-conventions.md format.

## Flags

| Flag | Scope | Behavior |
|---|---|---|
| `--type <type>` | Standalone | Set diagram type; skips heuristic inference. This is the primary flag for standalone `/brains:diagram` calls. |
| `--max-diagrams N` | Auto-trigger | Allow up to N diagrams (1-5, default 1) per distinct heuristic. |
| `--no-diagram` | Auto-trigger | Suppress all diagram generation. |
| `--diagram <type>` | Auto-trigger | Force a specific type, overriding heuristics and `--max-diagrams`. Passed by `/brains:brains` step 8; dispatched internally as `--type <type>` to this skill. NOT a user flag for standalone calls — use `--type` instead. |
| `--kroki-cloud` | Both | Opt-in to kroki.io cloud; requires explicit interactive consent. DISALLOWED in auto-trigger mode — source-only fallback is used instead. |

> **`--type` vs `--diagram` — why two flags?** These are flags in two different skills, not two versions of the same flag.
> `--type` belongs to `brains:diagram` (this skill): it selects the type when invoking the skill directly.
> `--diagram` belongs to `brains:brains`: it is a pipeline-level override that forces a specific type before the auto-trigger heuristic runs, then gets passed down to this skill as `--type`. A user invoking `/brains:diagram` directly should always use `--type`; `--diagram` is only relevant when invoking `/brains:brains`.

`--max-diagrams` active v0.4 priority order when N > 1: `state > flowchart > C4`  
Reserved future slots (v0.5, inactive): ER (after state), sequence (after C4)

## Self-Correction and Regeneration

**Retry loop:** On renderer syntax error, append the error to generation context and retry once (exactly one retry). On second failure, write the placeholder below.

**Placeholder (second failure):**
```
flowchart TD
  A["Diagram placeholder — manual revision required\nSee: docs/adr/diagrams/<stem>-<type>.mmd"]
```
Omit SVG for placeholders. Add to ADR: `<!-- diagram generation failed after one retry; edit docs/adr/diagrams/<stem>-<type>.mmd manually -->`

**Ordered overwrite (sequential, not atomic):** Write `.mmd` first, then render SVG from the `.mmd` and write `.svg`. On `.svg` write failure due to Mermaid parse/generation error: delete any pre-existing `.svg` (stale artifact). On transient I/O failure: preserve the pre-existing `.svg` (last-known-good).

**Auto-trigger marker:** First line of every generated `.mmd` MUST be exactly (no leading whitespace, no BOM): `%% auto-generated by brains:diagram — remove this line to protect manual edits`

**Option-5 regeneration:** Enumerate `docs/adr/diagrams/` for `<adr-stem>-{state,flowchart,c4}.mmd` (anchored, no globs). If first line exactly matches the marker: regenerate. Otherwise: skip, log one-line note.
